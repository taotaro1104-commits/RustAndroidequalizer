# Rust EQ 0.4.3

Android13で報告された、バックグラウンドから戻ると設定が戻る問題を修正しました。

- Q=0.1をJSONから読み直す際のFloat/Double比較と、20kHzの対数スライダーの丸め誤差を修正。保存値が不正扱いされEQ全体が初期化されるケースを防ぎます。
- 過去の保存データに含まれる20kHz近傍の小さな丸め誤差を補正し、ほかのバンドやゲインを保持。外部から取り込む設定の検証は維持します。
- プリセット名・選択バンド・空間設定もEQと一緒に保存。負荷対策の一時的な品質変更は、保存した利用者の設定へ上書きしません。
- 取り込んだIR/SOFAをキャッシュではなくアプリの保存領域へ置き、キャッシュ削除で失われないようにしました。
- 画面を閉じる際にアプリ独自の同期ディスク書き込み待ちを行わず、保存完了確認をIOスコープへ移しました。
- 待ち受けが実際に開始されてから対象アプリを開きます。開始できない場合は起動失敗を表示し、接続できた場合は古い待機メッセージを消します。

YouTubeを開けることと、音声へEQを適用できることは異なります。本方式は対応する音声セッション通知が必要です。動画を停止して開き直しても通知が来ない再生には適用できません。任意の他アプリ音声をRust DSPへ強制転送する機能や、root権限を使う処理は追加していません。端末・YouTubeのバージョンによる対応を保証するものではありません。

Android13 / x86_64で全31テスト成功、スキップなし。実際のプロセス終了を挟む保存・復元の2段階検証、同一署名の0.4.2からの更新、旧保存データの補正と対象アプリ設定の保持を確認。debug / releaseビルドとLint、v2 / v3署名、16KB整列も確認しました。詳細とYouTube検証の範囲は[検証記録](0.4.3.json)を参照してください。arm64実機での動作・すべてのYouTube再生条件は今回の検証範囲外です。
