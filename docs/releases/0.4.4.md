# Rust EQ 0.4.4

YouTubeなどが音声セッションを通知しない場合に、実セッションを探す「拡張検出」を追加しました。初期値はオフです。「ツール → 他アプリにもEQ」で対象を選び、拡張検出をオンにして、設定方法に表示されるADBコマンドでDUMP権限を付与してください。戻って「権限を確認して再検出」を押し、再生後に対象アプリの「端末EQに接続済み」を確認します。

- 選択アプリのUIDと正のセッションIDを確認し、既存の端末EQへ接続。通知のあるアプリは従来の方式も継続します。
- 履歴・非再生状態・自分のUID・曖昧なshared UIDを除外。Android13の非稼働行の表記にも対応しました。
- 読み取りの時間・容量を制限し、メインスレッドで待ちません。停止・選択変更・オプション解除後に古い結果を適用しません。
- 権限不足・形式の違い・時間切れを日英で案内。拡張検出の設定と対象アプリを保存し、プロセス終了後の復元も確認しました。
- root・録音・画面共有・session0を使いません。今回Shizuku設定画面や他アプリPCMのRust DSP処理は追加していません。

Android13 / x86_64で全37件、単体9件、Rustワークスペースのテストを実行。同一署名の0.4.3から更新し、署名済みrelease版でも通知を送らない別UIDプレーヤーの接続を確認しました。ビルド・両Lint・署名・16KB整列を確認済みです。専用AVDのSystem UI応答停止を避けるため、試験に不要なGoogleサービスと画面アニメーションを停止しています。詳細は検証記録を参照してください。

利用者端末や現行YouTubeでの接続成功は未確認です。検証用の旧YouTubeは更新要求画面で止まったため、fixtureの成功をYouTubeの成功とは扱っていません。端末の音声経路・EQ実装・診断形式による制約があります。
