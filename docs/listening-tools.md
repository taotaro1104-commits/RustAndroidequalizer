# 聴き比べ・音色合わせツール

Rust EQ 独自の「検証できるイコライザー」機能です。いずれも制御側（Kotlin）の処理で、リアルタイム音声スレッドには手を入れていません。

## 1. 音量をそろえた A/B 比較と ABX テスト（ツールタブ）

- A = いまの設定、B = 同じ音で EQ カーブだけをフラットにしたもの。
- 音量が大きい側のほうが良く聞こえやすいため、**大きい側のプリアンプを下げて推定ラウドネスをそろえます**（上げることはしません）。
- 推定方法: プリアンプ込みの EQ 応答を 20 Hz–20 kHz で、ピンクノイズ（対数軸で一様）× A 特性の重みで平均。疑似 BASS・エコー・コンプレッサーは含みません。精度は約 ±1 dB です。
- ABX: 毎回 X を A か B のどちらかにランダムに割り当て（画面には表示しません）、聞き分けて回答します。10 回の結果から、**当てずっぽうでその正解数以上になる確率**（片側二項検定）を表示します。5% 未満なら「聞き分けられている」と表示します。
- A/B 中は設定の変更と保存を止めます。終了すると元の設定に戻ります。

## 2. 音量連動ラウドネス（サウンドタブ）

- 端末のメディア音量が基準（80%）より下がると、低域は最大 +12 dB、高域は最大 +5 dB（強さ 100% のとき）まで滑らかに持ち上げます（等ラウドネス曲線の近似）。
- 持ち上げた最大量だけプリアンプを下げ、クリップを避けます。
- 保存される EQ カーブは変わらず、エンジンに送る設定だけを導出します。音量は 200 ms ごとに確認します。
- 補正はバンド中心周波数で行うため、31 バンドでは正確、バンド数が少ないと近似になります。

## 3. お手本の曲に音色を近づける（ツールタブ）

- お手本の曲と、いま読み込んでいる曲を、端末のコーデックでデコードして平均スペクトル（31 バンド）を求め、差を 31 バンドのゲインにします。
- 全体の音量差は取り除き、隣のバンドと平滑化し、±12 dB に制限します。強さは 40 / 70 / 100%。
- 各曲の中央付近、最大 90 秒を解析します。ツールタブから元に戻せます。
- 平均的な音色バランスを近づけるものです。曲の構成や録音の違いにより、聴感上同じになるとは限りません。

## 4. 自動プロファイル（ツールタブ）

- 音の設定をまるごと、**特定の曲 > 夜間（22:00〜6:00）> 出力機器（Bluetooth／有線・USB／スピーカー）** の優先順位で自動切替します。
- 条件が変わった瞬間にだけ切り替えるため、手動の調整とは競合しません。該当プロファイルがなくなると、切替前の設定に戻ります。
- 先に音を整え、各ボタンで状況ごとに保存します。

## 5. 聴力テストによる個人補正（ツールタブ）

- 250 Hz〜8 kHz の6周波数で、小さい音から5 dBずつ上げて聞こえた時点を記録します。
- 端末・ヘッドホンの校正がないため、1 kHz を基準にした形だけを使い、一般的な静寂時閾値の形を差し引きます。ハーフゲイン則で聞こえにくい帯域だけを最大 +12 dB 補正します。医療用の検査ではありません。

## 6. テンポ同期エコー（空間タブ）

- 曲をデコードしてテンポを推定（60〜180 BPM、オンセット包絡の自己相関）し、1/16・1/8（3連・付点）・1/4（付点）の長さでエコー時間を設定します。範囲外は 2 倍／半分に折り返します。

## 7. スピーカーと部屋の校正（ツールタブ）

- ピンクノイズを鳴らしてマイクで録音し、31バンドの応答から山を中心に控えめに補正します（カット最大 9 dB、持ち上げ最大 3 dB）。
- **録音権限は、この機能を押したときだけ許可を求めます。** 音声はメモリ上で解析し、保存も送信もしません。UNPROCESSED 音源があれば使います。
- スマホのマイク特性は完全にフラットではないため、結果は耳で確認してください。

## 検証

- 単体テスト（JVM）: ラウドネス推定、ABX 統計、補正カーブ、FFT/帯域解析、EQ マッチ。
- 端末テスト（エミュレータ）: WAV のデコード、スペクトル・テンポ解析、プロファイル保存、出力機器の分類、部屋測定が結果かエラー表示で終わること。
- 聴感評価と実機での確認は未実施です。
